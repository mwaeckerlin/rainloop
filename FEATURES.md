# Features

Numbered register of every feature of the version line 1; a number is never reused. Every feature is covered by tests listed in [TESTS.md](TESTS.md); the guard `tests/docs-contract.sh` fails when a feature has no test. F1 and F2 were found in the image `mwaeckerlin/rainloop:php-fpm` of 2026-07-16 and are kept as they were; F3 and F4 came with the rebuilds of this line, F5 with its compose example.

- **F1 — SnappyMail webmail behind nginx.** The user opens port 8080 of the nginx container and gets the web interface of SnappyMail, the newest release whose download tarball exists; a release published before its files is skipped until they are there. The nginx container serves the static files of that release and passes every PHP request to the php-fpm container under the name `snappymail`. The admin panel answers at `/?admin` for the user `admin`; on its first visit SnappyMail writes a generated password into `_data_/_default_/admin_password.txt` in the data volume.
- **F2 — Data in the volume `/app/data`.** Everything SnappyMail writes, configuration, accounts and cache, lies in `/app/data`, the volume the php-fpm image declares; the compose example mounts its named volume `data` there. A new php-fpm container on the same volume finds everything the old one wrote.
- **F3 — PHP with the fix of CVE-2026-109618 and CVE-2026-109619.** The php-fpm image runs PHP 8.5.12 or newer on the line 8.5, 8.4.27 or newer on the line 8.4, or a later minor line. It keeps the mitigations of `mwaeckerlin/php-fpm` on top: session upload progress is off and the php-fpm pool locks it off, and the pool locks fatal error backtraces off, so neither SnappyMail nor a request can switch them on again.
- **F4 — Published for amd64 and arm64.** Every push to the branch `1` builds both images natively for both architectures and publishes them on Docker Hub as `mwaeckerlin/rainloop:php-fpm` and `mwaeckerlin/rainloop:nginx`, the names the image of 2026-07-16 had, and as `mwaeckerlin/rainloop:php-fpm-1` and `mwaeckerlin/rainloop:nginx-1`; each name also with the day of the build, the version and both together (`php-fpm-20261031`, `php-fpm-1.11.3`, `php-fpm-1.11.3-20261031`). The hourly check of the branch `master` starts this branch too, and it builds again when a parent image or a download changed, or the published image is a week old.
- **F5 — The published address is a setting.** The compose example publishes the nginx container on port 8080 of every address of the host, IPv4 and IPv6; `BIND_ADDRESS` limits it to one address, for example `127.0.0.1` for the own machine only.
